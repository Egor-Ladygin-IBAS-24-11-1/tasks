# ПР №8. Следы вредоносного ПО в Linux

## 1. Что было посажено

| Механизм | Место | Команда/файл |
|----------|-------|-------------|
| Cron | crontab пользователя | `/tmp/.hidden_malware/backdoor.sh` |
| Systemd | `~/.config/systemd/user/` | `system-helper.service` |
| Shell profile | `~/.bashrc` | `/tmp/.hidden_malware/backdoor.sh` |
| Процесс | `/tmp/.hidden_malware/` | `listener.sh` на порту 4444 |

## 2. Что нашли — процессы

**Команда:** `ps aux | grep '/tmp'`  
**Результат:**  
```bash
egor  7836  0.0  0.1  6940  3308  ?  Ss  12:41  0:00  /bin/bash /tmp/.hidden_malware/backdoor.sh
egor  7837  0.0  0.1  6940  3280  pts/0 S 12:41  0:00  /bin/bash /tmp/.hidden_malware/listener.sh
```
**Что подозрительно:** Запуск исполняемых bash-скриптов напрямую из директории `/tmp`. В нормальных условия системные и пользовательские процессы не должны исполнять код из временных директорий с глобальными правами на запись — это классический индикатор компрометации (staging area для malware).

**Дерево процессов (`ps axuf | grep hidden`):**  
Видно, что `listener.sh` (PID 7837) является родительским процессом для `nc -l 4444` (PID 7839), что подтверждает создание бэкдора для обратного соединения.

## 3. Что нашли — сетевые соединения

**Команда:** `ss -tulnp | grep 4444`  
**Подозрительный порт:** 4444 (TCP LISTEN)  
**Процесс:** `nc` (PID 7839)  

**Команда:** `sudo lsof -i :4444`  
**Результат:**  
```bash
COMMAND  PID USER  FD   TYPE DEVICE SIZE/OFF NODE NAME
nc      7839 egor   3u  IPv4  91660      0t0  TCP *:4444 (LISTEN)
```
**Как lsof связывает порт с процессом:** Утилита `lsof` обращается к ядру ОС и сопоставляет файловые дескрипторы (в данном случае сетевой сокет IPv4) с конкретным PID и именем исполняемого файла (`nc`). Это позволяет однозначно доказать, какой именно процесс удерживает порт, даже если он маскируется.

**Команда:** `sudo lsof -p 7837` (анализ открытых файлов listener-процесса)  
**Результат:** Процесс держит открытыми сам скрипт `/tmp/.hidden_malware/listener.sh`, стандартные библиотеки `libc.so.6` и терминал `/dev/pts/0`. Это говорит о том, что процесс активен, работает в контексте пользователя и использует стандартные системные вызовы для ожидания входящих соединений.

**Команда:** `sudo lsof | grep deleted`  
**Результат:** Найдены только удалённые memfd-файлы процесса `pipewire` (системный аудио-сервер). Вредоносных удалённых файлов (техника fileless malware) обнаружено не было.

## 4. Что нашли — автозапуск

### Cron
**Вывод `crontab -l`:**  
```bash
@reboot /tmp/.hidden_malware/backdoor.sh
*/5 * * * * /tmp/.hidden_malware/backdoor.sh
```
**Что подозрительно:** Наличие задач, запускающих скрипты из `/tmp`. Запись `@reboot` обеспечивает выживаемость вредоноса после перезагрузки, а `*/5` гарантирует, что если процесс упадёт, он будет перезапущен каждые 5 минут.

### Systemd
**Вывод `systemctl --user list-unit-files`:** Присутствует `system-helper.service` в состоянии `enabled`.  
**Содержимое unit-файла:**  
```ini
[Service]
ExecStart=/tmp/.hidden_malware/backdoor.sh
Restart=always
RestartSec=10
```
**Что подозрительно:** Сервис маскируется под легитимный системный помощник (`system-helper`), но исполняет файл из `/tmp`. Директива `Restart=always` делает его крайне устойчивым к ручному удалению (systemd будет бесконечно перезапускать его).

### ~/.bashrc
**Строка которую нашли:**  
```bash
115:# system update helper
116:/tmp/.hidden_malware/backdoor.sh &
```
**Где находится:** Строки 115-116 в `/home/egor/.bashrc`.  
**Что подозрительно:** Маскировка под "помощник обновления системы". Скрипт запускается в фоне (`&`) при каждом открытии нового терминала пользователем, что позволяет вредоносу закрепиться в системе без использования системных демонов.

## 6. Связь с нормативкой

Какие меры ФСТЭК №17 реализует эта проверка:
- **АНЗ.2** (Оценка уязвимостей и анализ защищенности): Поиск несанкционированных механизмов автозапуска позволяет выявить уязвимости конфигурации ОС и несанкционированное ПО.
- **АУД.4** (Регистрация событий безопасности): Анализ сетевых соединений (открытие порта 4444) и запуск подозрительных процессов относятся к мониторингу аномальной активности в ИС.
- **ЗИС.17** (Защита от вредоносного кода): Прямое обнаружение, анализ и удаление вредоносных скриптов, имитирующих поведение бэкдоров, соответствует требованиям по нейтрализации вредоносного ПО.

## 7. Результаты зачистки

После выполнения команд по остановке сервисов, очистке `crontab`, удалению строк из `~/.bashrc` через `sed`, уничтожению процессов (`pkill`) и удалению директории `/tmp/.hidden_malware/`, был повторно запущен диагностический скрипт `/tmp/check-system.sh`.

**Что изменилось:**  
Все поля отчёта скрипта изменились с "найдено" на "чисто". 
- В `crontab` отсутствуют записи с `/tmp`.
- В `systemctl` сервис `system-helper.service` больше не отображается в enabled.
- В `~/.bashrc` grep не находит подозрительных строк.
- В `ps aux` нет процессов из `/tmp`.
- В `ss -tulnp` порт 4444 больше не слушается.
Система полностью очищена от следов учебного вредоноса.

## 8. Выводы

В ходе практической работы мы изучили механизмы персистентности (закрепления) вредоносного ПО в ОС Linux. 

**Самые неочевидные места:**  
1. **Пользовательский systemd (`~/.config/systemd/user/`)** — опасен тем, что для создания такого сервиса не требуются права `root`, но он позволяет автоматически запускать вредонос при входе пользователя в систему и автоматически перезапускать его при падении.
2. **Профильные файлы (`~/.bashrc`)** — классический вектор атаки, который сложно заметить при беглом осмотре системных демонов, так как вредонос активируется только при интерактивной работе пользователя.

Инструменты `lsof` и `ss` оказались критически важными для связки сетевой активности (открытых портов) с конкретными PID и исполняемыми файлами, что является основой сетевого форензики.
